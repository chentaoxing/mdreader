# shell/win-wpf —— Windows 界面壳（.NET 10 WPF）

产品名：**MD文档阅读助手**（窗口标题、程序集 Product、打开方式里的名字都是它；
exe 仍叫 `MdFileAssistant.exe`、C ABI 仍是 `mdfile_*` 前缀——这两个牵动已注册的打开方式与四平台绑定命名，要改单独提一次）。

一句话：**文件里的字节一个不由界面决定**。要不要改、改哪儿、能不能改，全部来自 `mdcore_ffi.dll`
（与 CLI、以及以后四个平台共用的同一份核心）；界面只决定**屏幕上怎么摆**。

## 构建与运行

```bash
cd shell/win-wpf
dotnet build -c Release
bin/Release/net10.0-windows/MdFileAssistant.exe 某个文件.md
```

只需要 .NET 10 SDK + Windows 桌面运行时（本机已具备），**不需要 Rust 或 MSVC**——
`mdcore_ffi.dll` 由交叉工具链产出后放进 `Native/`，构建时自动拷到 exe 同目录。
缺这个 dll 时程序会明确报一行提示，不会静默变成"什么都能干但没结果"。

## 两栏各是什么

| | |
| --- | --- |
| **左：源文件** | 等宽、不折行、不隐藏——就是那份字节。只读，永不写回，也不随阅读模式变 |
| **右：阅读视图** | 给人读的版式：段落接回整句、行长封顶、标题层级与节奏、列表悬挂缩进、引用块、代码块、表格 |

顶栏四个开关：预设（决定核心用哪套规则）、语法符号（原样 / 弱化 / 隐藏）、字号、视图（对比源文件 / 专心读）。
**这四个都只影响屏幕**，写盘的字节由核心返回的 `rendered` 决定，跟它们没有因果关系。

## 阅读视图具体做了什么

`Reading/ReadingRenderer.cs` 把 Markdown 解析成块（标题 / 段落 / 列表 / 引用 / 围栏 / 表格 / front matter），
然后：

- **接回硬换行**：源文件里为了书写方便手动断的行，在屏幕上并回一段；中文与中文之间不补空格，
  英文之间补一个空格；行尾两个空格或 `\` 视为作者本意的换行，保留。
- **行长封顶**：`MaxPageWidth = 880 × 字号系数`，标准字号约 40 个汉字一行。窗口拉宽也不会变成一堵墙。
- **标题节奏**：h1/h2 带下划线分隔，字号 25/21/18/16.5/15.5，行高 1.5–1.6 倍，`KeepWithNext` 防止标题掉在页尾。
- **列表**：按源缩进换算悬挂缩进；任务项 `[x]` 在隐藏档渲染成 ☑ / ☐。
- **表格**：隐藏档画成真表格（表头底色、隔行底色、按 `:---:` 对齐、`\|` 还原成单元格里的竖线）；
  原样与弱化档竖线属于"要留下的阅读字符"，仍按行显示。
- **代码块**：整块底色 + 等宽 + 语言标签；**引用块**：左侧竖条 + 底色；**front matter**：淡灰元信息块。
- **语法字符**：弱化档染淡灰，隐藏档不上屏（`**粗**` 直接加粗、`` `码` `` 直接以代码样式呈现）。
  链接目标不丢：隐藏档把 URL 挪到 ToolTip 与 `AutomationProperties.HelpText` 里。
- 超过 80 万字符不做富文本，降级为纯文本上屏并写明原因（几 MB 的 `FlowDocument` 会把界面拖死）。

**这些全部只在显示层。** 本类没有任何写文件的路径；`MainWindow` 的保存按钮写的是核心返回的字节，
且目标路径等于原文件时直接拒绝。

## 打开中文 Windows 老文件时（`Shell/TextDecode.cs`）

核心只吃 UTF-8，这是五平台逐字节一致的前提，不能为兼容去动它。所以转码放在这一层，
而且**只在内存里**：原文件字节不动，状态条会写明「现在读的是 UTF-8 副本」，另存出去的是一份 UTF-8 新文件。

判定顺序是「能确定才动手」，猜不出来就拒读：

1. 有 UTF-16 BOM → 按 UTF-16 解；
2. 字节里含 NUL → 直接拒（顺手堵住了「无 BOM 的 UTF-16LE 恰好是合法 UTF-8、会被当正文收下」这个洞）；
3. 严格 UTF-8 能解 → 就是 UTF-8，**字节原样交给核心，一个都不转**；
4. 都不行 → 先试 GB18030（GBK 的超集，2 字节段与 GBK 完全一致，四字节生僻字才不会解坏），再试 GBK；
   解出 NUL 或替换符超过千分之一（多半是拿二进制当中文读）就不认；
5. 全都不行 → 明说「认不出的编码我不猜，文件也没动」，两栏留空。

实测（同一份内容的四种编码各造一个文件，逐个真开一遍）：UTF-8 / GBK / UTF-16LE 三份的正文校验和
完全相同（`284810…085`），都是 6 处结构变化、正文变化 0；带 NUL 的伪 PNG 与无 BOM 的 UTF-16LE
都被干净拒读，文件未被改写。

### 写回去的那条路有专门的逐字节验收（`tests/encoding-roundtrip/`）

读对了不代表写得回去。0.2.0 就是这么翻车的：带 BOM 的 UTF-8 存回去 BOM 整个没了，
GBK 文件一律报「连长度都算不出来」。这两条界面点不出来，只有喂真字节、比真字节才看得见，
所以立了一个控制台工程专门盯它——`dotnet run --project shell/win-wpf/tests/encoding-roundtrip`，
退出码就是失败项数（当前 24 项全绿）。

它引用的是 `Shell/TextDecode.cs` **正本**（csproj 里 `Compile Include ../../Shell/TextDecode.cs`），
不是复制一份去测；改坏真代码，这个测试立刻红。跑的是 `tests/encoding-roundtrip/fixtures/` 下四份
刻意保留字节特征的样本（UTF-8/CRLF、UTF-8 带 BOM/CRLF、UTF-16 LE、GBK），每份三问：
标签对不对、**一字不改写回是否逐字节还原**、改一行后写回是否保留 BOM/前导且不许多出一份。
外加 cp936 遇到写不出的字必须拒写并报出是哪个字符（GB18030 是全 Unicode 超集，emoji 不该误拒）、
无 BOM 的 UTF-8 不许被补上 BOM、未知标签拒写。
这些 fixture 在 `.gitattributes` 里标了 `-text`：一旦被 git 的换行规范化动过，
「写回去和原文件一模一样」这条验收就变成自证。

## 编辑模式（顶栏「编辑：关 / 开」）与保存模型

这个软件对外的承诺是"不改你的文件"。编辑是那条承诺唯一的例外，所以它被做成**必须你亲手开、而且记不住**：

- 每次启动、每次换文件，开关都回到「关」。编辑状态本身**不写进 `settings.json`**——
  一个会被记住的写盘开关，迟早会在某次用户忘了自己开过的时候改错文件。
- 点「编辑」时先弹 `Shell/EditWarningWindow`：880×660 的独立窗口，标题 30 号字、正文 18–21 号，
  默认按钮是「取消，继续只读」（回车=取消）。只有点最后一颗「我了解，开始编辑」才真的开。
  不用 `MessageBox` 是因为它放不下"会怎样、不会怎样"这几条。这屏警告可以在设置里关掉。

### 保存去哪（顶栏「设置」里可改）

| 动作 | 默认 | 说明 |
| --- | --- | --- |
| 编辑后点「另存为新文件」 | 写 `原名.改于20261103-1246.md` 到**源文件同目录**，原件一个字节不动 | 同一秒连点两次会自动加 `-2` 后缀，不互相盖 |
| 编辑后点「保存回源文件」 | **不存在**，除非在设置里把保存目标改成「覆盖源文件」 | 改完之后按钮文案、左栏红字表头都跟着变 |
| 「另存为优化版…」 | 起始目录 = 设置里的另存目录，留空则退回源文件所在目录 | 这是排版结果的出口，从来不是 `保存` |
| 定时自动存档 | 开着编辑且**有未保存改动**时，每 2 分钟写一份到缓存目录 | 缓存目录默认 `%LOCALAPPDATA%\MdFileAssistant\autosave`，可改；每个源文件默认只留最新 40 份 |
| 关软件 | 有未保存改动时**先写一份缓存**，再弹「是 / 否 / 取消」 | 选「否」也找得回来，因为缓存是问之前就已经落盘的 |
| 关掉编辑 | 有未保存改动时先问，确认后**写一份缓存再丢弃** | 同上 |

设置项一共五个开关/字段：保存目标、另存默认目录、自动存档（开/间隔/目录/保留份数）、
编辑前弹确认、关闭时询问。都存 `%APPDATA%\MdFileAssistant\settings.json`，纯文本可直接删。
`Settings.Load()` 会校验：保存目标不认识就退回「同目录新文件」，间隔和份数越界就退回默认——
宁可带着默认值跑，也不要带着一个不认识的目标去写盘。

缓存写不进原编码时（比如 GBK 文件里打了 emoji）会退成 UTF-8 并在文件名上标出来：
**缓存是拿来找回东西的，不是拿来替换原件的**，所以它不必和原件同编码。

### 覆盖源文件这条路上的四道闸

`OnSaveSrc()` 按顺序过四关，任何一关不过就**一个字都不写**，状态条会说是哪一关：

1. **磁盘冲突**：写之前重读一遍文件，字节和打开时不一样就说明别的程序动过它——不覆盖、不合并，
   把两个选择摆给你看。
2. **原编码写回**：`TextDecode.Encode()` 按当初判出的那个 Label 编回去（UTF-8 连 BOM 的有无一起抄、
   UTF-16 LE/BE 补回 BOM、GBK / GB18030 走 `WideCharToMultiByte`）。中文编码带 `WC_NO_BEST_FIT_CHARS`，
   装不下的字**宁可拒绝写也不换成问号**，报错里会指出是哪个字符、码位多少。
3. **保命副本**：第一次写之前把原件复制成同目录的 `原名.md.bak`，**已存在就不覆盖**——
   所以它永远是你改动之前的样子。这一份建不出来（目录只读等）就直接不写，因为弹窗里答应了有备份。
4. **原子替换**：同目录隐藏临时文件写完再 `File.Replace`；它失败才退回 `File.Move(overwrite)`，
   状态条会告诉你是哪一种。

换行风格与 BOM 都按原样保留，不会因为点了"保存"就顺手把整份文件的行尾重写一遍。

真机验收（`本地验证/编辑模式-实测-2026-11-03.txt`，全程用 UIA 真点按钮，不是命令行模拟）：
一份 UTF-8 + CRLF、111 字节的样本，开编辑 → 加一行 → 保存，磁盘上变成 151 字节，
**CRLF 10 处、裸 LF 0 处、孤立 CR 0 处、BOM 仍然没有**，逐行 diff 只多出一行、少零行；
`.bak` 的 md5 与改动前的原件**逐字节相同**（`5d3fb1b6…d680`）。
再把文件在外部改一下、回到界面点保存 → 弹出拒绝，磁盘保持外部那份不变。
"一个字没改直接保存"这条没测：`_dirty` 为假时按钮直接回「左栏没有改动，不用保存」，压根不写盘。

真机点出来的一个坑：`MessageBox` 开着的时候 WPF 仍在泵消息，连点「保存回源文件」会**叠出第二、第三个模态框**
（实测叠了三个，内容一样，都拒绝写入，没造成数据问题，但很难看）。所以每个模态框前后都加了 `_busy` 闸门，
`OnEdit` / `OnSaveSrc` 开头也各挡一次。

### 一个不那么显眼的改动

`Show()` 原来是无条件 `ViewSrc.Text = _srcText`。编辑模式下这会要命——切个阅读模式或字号就把用户
还没保存的改动抹掉、光标也没了。现在改成"内容真的不一样才回写"。
配套地，编辑时停手 350 ms 会用改后的文本重跑一次核心，右栏读到的就是左栏现在的样子。

## 明暗主题（`Theme/ThemeManager.cs`）

颜色**只在这一处定义**：`Light` / `Dark` 两张语义色表（`WindowBg`、`TextPrimary`、`Markup`、`CodeBg`、
`TableBorder`…），XAML 全部走 `DynamicResource`，阅读视图渲染当时取色。所以不会出现"某块忘改还是白的"。

三档：跟随系统（默认）/ 浅色 / 深色。跟随档读 `HKCU\...\Themes\Personalize\AppsUseLightTheme`
并订阅 `SystemEvents.UserPreferenceChanged`——在 Windows 设置里切夜间模式，窗口当场跟着变，不用重启。
选择存 `settings.json`。

两个只有真点界面才暴露的坑：

1. **XAML 里的 `IsChecked="True"` 会在解析阶段就触发 `Checked`**，那一刻同组其它控件的字段还是 null，
   处理器里读它们直接 `NullReferenceException`——第一次真启动就是这么崩的。所有 `Checked` /
   `SelectionChanged` 处理器一律先 `if (!_ready) return;`。
2. **ComboBox 用默认主题模板时，选中区底色写死在主题资源里**，只设 `Background`/`Foreground`
   会得到"白底 + 浅灰字"，深色模式下等于看不见（截图确认后才修）。解法是自带一个极简模板，
   底色直接吃 `FieldBg`。TabItem 同理，默认模板自带浅色渐变。

## 自更新（`Shell/NetGuard.cs` + `Shell/Updater.cs` + `Shell/SelfReplace.cs`）

发布形态照 ChinaSeal：**portable zip**（`mdreader-<版本>-portable.zip`，自包含、解压即用），
更新 = 解压覆盖应用目录，不出安装包。仓库 `chentaoxing/mdreader`，换仓只改 `Updater.Repo` 一行。

四条护栏，逐条对应 ChinaSeal 那套真机踩过坑的实现：

- **出网闸门**：只允许 https；主机必须在白名单；解析出来的 IP 落在内网 / 回环 / 链路本地 /
  CGNAT / 保留段一律拒绝（防"白名单被 DNS 指到 169.254.169.254"这类 SSRF）；
  **重定向逐跳再校验一遍**，不然一个 302 就绕过白名单了。
- **检查双路线**：`api.github.com/.../releases/latest` 优先；403 限流或异常时回退
  `releases.atom`（不占 API 配额），再抓 `expanded_assets/<tag>` 找直链。
  匿名配额是按出口 IP 算的，走代理时很容易吃 403——所以两条路都得在。
- **下载**：先用 `Range: bytes=0-0` 探测总长与是否支持分块，支持就 4 路并行写各自 `.part{i}.tmp` 再合并；
  15 秒窗口内零进度判停滞、不足 15MB 判龟速并**换下一个候选源**（最后一个源容忍磨完）。
  国内网络下 GitHub 常是"连得上但磨"，这条决定能不能更新成功。
- **落盘边界**：只准写 `%TEMP%\MDReader-Update`；文件名取 basename + 字符白名单 + 目录 containment，防路径穿越；
  尺寸下限与 `Content-Length` 双重校验，对不上就删掉重来。

覆盖动作交给 `helper.bat`（Windows 锁着正在运行的 exe，进程内改不掉自己）：解压到暂存 →
等本进程退出 → `xcopy` 覆盖 → **确认新版 exe 真的解出来了**才继续 → 清理 → 拉起新版 → 自删。
每一步都往 `helper.log` 里写，出问题时有一处可查。ChinaSeal 的 0.4.20 修的就是
"点了安装、软件退出、然后没有然后"，这个坑不必再踩一遍。

**bat 正文必须纯 ASCII**：这台机器上应用目录常含中文，中文路径写进 .bat 会被 cmd.exe 按 OEM 码页读坏；
改成用**参数**传进去（命令行是 UTF-16 进来的），bat 本体一个汉字都没有。

token 只从 `GH_TOKEN` / `GITHUB_TOKEN` 或 `%APPDATA%\MDReader\github-token.txt` 读，
绝不去翻别的工具的凭据。

**触发方式**：顶栏「检查更新」按钮。「启动时检查」默认开（照 ChinaSeal），启动 3 秒后静默查一次，
只在真有新版时把按钮变成「有新版本 vX」并在状态条留话，不打扰正在读的东西；
取消勾选后只有手动点才联网。**这是本程序唯一的出网行为**——README 里"离线"那句已按这个事实改写。

## 逐条接受 / 拒绝

改动清单里取消勾选某条规则，即调 `mdfile_rebuild` 重建，右栏与状态条实时跟着变。
界面不参与任何排版计算——它只是把「接受哪些规则」这个决定传给核心。

## 状态条上写的是凭据，不是安慰话

```
✓ 正文内容变化 0 · 结构变化 6 处 · 校验和 284810…085 前后一致 · 收敛轮次 2 · 阅读视图的版式只在屏幕上，不写回文件
```

校验和比的是字符串（`checksum_original_str` / `checksum_str`），**不是 JSON 里的数字**——
u64 是 19 位十进制，超过 2^53，用数字比会丢末位。取不到校验和时一律按「不证明」处理，
状态条变成「不允许保存」，宁可不给存也不给一个没验过的结果。

## 「设为 .md 打开方式」按钮的实话

它只做程序能合法做的部分：在 `HKCU\Software\Classes` 注册 ProgID 并把本程序挂进 `.md` 的**打开方式列表**
（写之前 `reg export` 备份，写之后打印条目数变化，同一个按钮可撤销；撤销前会核对打开命令确实指向本程序，
不是就拒绝删）。

**Windows 10/11 的"默认应用"由 UserChoice 哈希保护，第三方程序不能合法静默改写**，
所以按钮的第二步是打开 `ms-settings:defaultapps` 让人亲手点。界面文案就照这个写，不假装已经设好。

### 别的软件（豆包等）的「打开方式」列表从哪来

豆包桌面端的那个下拉不是它自己维护的白名单。它的二进制里有 `SHAssocEnumHandlers`，日志
（`%LOCALAPPDATA%\Doubao\User Data\sdk_storage\log\saman_*.log`）里每次开菜单都会打一行
`[open_with] QueryOpenWithApps ext=md, count=N`，并为每个 handler 打 `[open_with] icon location=[...]`。
也就是说：**它问的是 Windows 的 handler 枚举，我们没注册，它就不可能列出来。**

用同一个 API 在本机实测（`ASSOC_FILTER_RECOMMENDED`）：注册前 10 项，注册后 12 项，
新增的是我们和一条 `GetName` 直接失败的悬空项；`ui` 名依次是
Obsidian / WorkBuddy / ima / DingTalkDoc / Antigravity IDE / Muses / QQ浏览器 / Trae CN /
cmd / **MD文档阅读助手** / 记事本。豆包界面只露出其中 5 条，它自己还有一层过滤
（二进制里有 `saman-open-with:browser`、`saman-open-with:image-viewer` 和
`[open_with] open rejected: filtered app`），这层归它，我们改不了。

所以注册这一步之外，代码里补了 `SHChangeNotify(SHCNE_ASSOCCHANGED)`：注册和撤销都广播一次。
不广播的话，已经开着的程序可能一直拿自己缓存的那份关联表。**这条没做对照实验**：本机是写完注册表、
立刻广播、然后才枚举的，所以"这次能被看见"到底取决于哪一步，我不知道。补广播是因为它是安装器的
标准动作，不是因为我证明了它是决定性的那一步。

仍未机器验证：**撤销注册**那条分支（代码审查过：删之前会核对 open command 确实指向本程序，不是就拒绝删）。
