# assets/brand —— 图标与品牌资产

## 这枚标在说什么

**一道标尺，四行文本，其中一行冲了出去。**

`MD文档阅读助手` 做的事就一件：把写给 AI 的 Markdown 按人的阅读习惯重新排。它最招牌的那个动作是
**给行长封顶**——AI 写的段落动辄几百字符一行，人眼跟不住，软件把它约束到约 40 个汉字。
所以标上那根竖线不是装饰，是"行长"本身：三行规规矩矩贴住它，最上面一行越过它 = 没约束之前的样子。

一层几何同时干两件事：**文本**（横条）+ **被封顶的行长**（竖尺与溢出）。去掉竖尺，剩下的是通用"列表"图标；
去掉溢出那行，"封顶"这个动词就没了——两者共用同一条边界，这才是融合，不是拼贴。

## 为什么不是之前那枚

旧版（`旧版/icon-simple.png`、`旧版/icon-master.png`）是"文档轮廓里一个向下箭头"，两个问题：

1. **它读作"下载"**。文档 + 向下箭头是通用下载符号，一款讲"给人读"的软件顶着一个下载图标是反向信号。
2. **它撞在品类公版上**。Markdown 的社区标（`dcurtis/markdown-mark`：圆角框 + M + ↓）已经被
   Flaticon / Icons8 / Streamline / Tabler / Ionic 等图标库复刻到泛滥，"圆角框 + 文档 + 箭头"和它只差一步。

细节版还有第三个问题：浅底叠浅底，单色与反白都不成立，16/24px 直接糊成一团。

## 筛查状态

**部分筛查**（2026-10-19/20，经本地 SearXNG：`google cse` 一路超时，只覆盖 duckduckgo / bing / baidu / sogou / 360）。
据此建立并遵守的 avoid map：

- 圆角方框 + M + 向下箭头（Markdown 社区标及其图标库变体）；
- 文档 + 向下箭头（下载符号）；
- 四行长度递减的纯"对齐"图标（工具栏公版）；
- 页形轮廓 + 右上切角（通用文件图标）；
- 眼睛 / 翻开的书（"阅读"类应用的另一处公版）。

**因此本文件不声明原创性或可注册性。** 这是设计方向筛查，不是任何司法区、任何类别的商标近似查询。

## 概念族与落选原因

| 族 | 配对 + 骨架 | 结果 |
| --- | --- | --- |
| F1 参差→齐平 | 重排动词 + 纯横条堆 | 16px 退化成"对齐"工具栏图标，品牌性不足 |
| F2 纸与折角 | 文档 + 折角与末行共边 | 折角斜线穿正文读成杂笔；简化后就是通用文件图标 |
| F3 MD 字形 | 首字母 + 文本列骨架 | 拼出来不可辨，且离 M↓ 公版最近 |
| **F4 行长封顶** | **文本 + 一道边界** | **入选**：首行溢出的 F4-C 均分 4.5，四行贴尺的 F4-A 4.2 |

评分口径：品牌契合 / 融合完整 / 已筛查区分度 / 最小尺寸可辨 / 单色可复现 / 文化与类别安全，1–5。
区分度一律封顶 3（筛查不完整）。

## 锁定的不变量（改任何一条都要重跑全套检查）

1. 一根右标尺 + 四行文本；**首行右端越过标尺**，其余三行右端贴住标尺。
2. 标尺只罩住被约束的三行，不穿过首行——否则"溢出"读不出来。
3. 全部笔画共用一个粗细 `1u` 与圆头半径 `0.5u`；行距 `2u`、间隙 `1u`（8u 网格）。
   上一版把行距算得比笔画还窄，四行叠成一整块黑——这是几何错误，不是缩放损失。
4. 整组向左做视觉补偿（质量偏右），按光学居中而不是几何居中。

## 响应式与最小尺寸

| 尺寸 | 用哪版 | 为什么 |
| --- | --- | --- |
| ≥ 32px | **完整标**（四行 + 标尺 + 溢出） | 四行才读得出"一段文本" |
| ≤ 24px | **微标**（三行 + 标尺，溢出加大） | 实测 2 行方案在 16px 读成直角括号"¬|"，文本义丢失，已否决；3 行是能读成文本的最少行数 |

已验：16 / 24 / 32 / 48 / 64 / 128 五档，纯黑单色、灰底、墨蓝反白三种底，见 `../../../../../本地验证/mark-qa.jpg`。
颜色不救几何：黑白先成立，才上 `#0B3B5C`。

## 文件清单

| 文件 | 用途 |
| --- | --- |
| `icon-mark.svg` | **矢量母版**（单色，`fill` 换色即用）。GitHub/文档、关于页、任何能放 SVG 的地方 |
| `icon-mark-white.svg` | 反白母版（深色背景上用） |
| `icon-mark.png` (1024) | 单色墨蓝位图 |
| `icon-tile.png` (1024) | 墨蓝圆角底 + 反白标：应用图标、头像、封面 |
| `png/16…1024.png` | 尺寸梯队（**tile 版**，应用图标用途） |
| `png/mark/16…1024.png` | 尺寸梯队（单色墨蓝版，文档用途） |
| `app.ico` | Windows 图标：16/24/32/48 为 BMP 项（老 shell 也认），64/128/256 为 PNG 项；16/24 用微标 |
| `favicon.ico` | 16/32/48 BMP 项，给 `report` 生成的离线 HTML 用 |
| `旧版/` | 被取代的细节版与简化版，仅存档，不再进任何构建 |

留白：四周留 `1u`（约图标高度的 1/8）不小于标尺到边缘的距离；`app.ico` 的圆角底按 Windows 惯例自带 20% 圆角，
不要再套一层容器。

## 它已经进了构建

`crates/mdfile-cli/build.rs` + `resources/mdfile.rc` 把 `app.ico` 与版本信息编进 Windows exe；
`.rc` 里图标路径是占位符 `@MDFILE_ICON@`，由 build.rs 换成绝对路径再交给 `windres` / `rc.exe`
（windres 按当前目录解析、rc.exe 按 .rc 所在目录解析，两边不一致，所以必须给绝对路径）。
资源编译器缺失时只发 `cargo:warning`，不断构建。
Windows 壳的 `shell/win-wpf/app.ico` 是这里的副本，换图后两边要一起更新。
